# 人声定位主导、ASR 辅助：初版实施记录

当前分支已实现短时人声方向稳定器、实时指针与 ASR 解耦、方向未知时仅显示转写，以及重连和清空文字时的状态分离。板端实际延迟和准确率尚待测量；长语音边界重叠、文本去重和丢段提示仍是后续工作。

## 改动前的延迟来源

采集每 32 ms 生成一个八通道音频块。`Pipeline.process()` 已在每块上计算 VAD、方向和可信度，结果也即时进入 UI 队列；但改动前 `Application.tick()` 在语句模式下不把实时跟踪角赋给指针。指针曾只由 `poll_asr()` 的识别结果驱动，所以必须先等句尾静音（当前 0.6 秒）、ASR 排队与推理、下一次 UI 轮询。说话很长时还会等到 5 秒强制切段。

改动前界面还把方向和文字绑定：方向未知的 ASR 结果只写到终端，ASR 空结果或错误会清除指针。

## 初版显示数据流

```text
8 通道采集（32 ms/块）
  ├─ VAD + 定位 + 短时方向稳定器 ──► UI 实时指针与扇区
  └─ 语音分段 ──► 后台 SenseVoice ──► 转写列表
                         ▲
                 同时附上该段方向快照
```

1. **独立实时方向状态。** `LiveDirection` 只消费 `sentence_direction_valid`、角度、置信度和时间戳。它使用最近 0.25 秒的有效人声块做圆周加权平均；累计 0.16 秒、方向集中程度达标后显示指针。窗口、有效时长、一致性和保持时间可配置。首次出现方向时直接定位；小角度变化平滑，大跳变要求 3 个连续一致的结果确认。
2. **让 UI 从定位结果更新。** 每次 `tick()` 都以最新实时方向状态决定指针；ASR `result` 只追加转写，不修改实时指针。未知方向的文本只显示转写本身，不附加方向标签。ASR 失败、队列繁忙或模型缺失不影响人声定位。
3. **明确指针生命周期。** 有效人声方向积累后指针出现；VAD 仍检测到人声时保留最近稳定方向，语音结束后保持最多 0.4 秒再隐藏。下一位说话者进入时按新方向重新确认。设备重检清空实时状态；清空转写只清空文字，不改变正在跟踪的声源。
4. **保留语句方向作为文字元数据。** 分句器仍计算该段加权平均方向，供每条转写显示。它不再是指针显示的前置条件。实时方向与转写方向可能在说话者移动时不同，界面应分别标注“当前方向”和“该段方向”。
5. **后续测量延迟。** 记录采集时间、定位完成、UI 首次显示、句尾、ASR 完成的时间戳；在 PI M2 上测首指向延迟和稳定跟踪延迟的 P50/P95。建议验收目标是首指向 P95 小于 300 ms，稳定后音频块到界面更新 P95 小于 100 ms；这是目标，尚未板端实测。

原有 `Tracker` 按单块结果判断，容易抖动或瞬时误指。短时圆周稳定器让速度和可信度可单独调节，并借鉴了 `Tracker` 的跳变确认思路。

## 长时间说话与 ASR

当前 `config.json` 将 `asr_max_seconds` 设为 **5 秒**，`asr_silence_seconds` 设为 **0.6 秒**。连续说话达到 5 秒时，分句器提交一个片段并继续采集后续片段；参数校验允许单片段最长配置到 30 秒。SenseVoice 在后台对每个片段做离线识别，没有逐词流式输出。

因此长时间连续说话可以被切成多段处理，但目前不能保证完整、连续的转写：片段边界没有重叠，词可能被切开；末尾人声不足 0.24 秒时会被丢弃；后台作业队列仅能等待两段，满时新片段直接跳过。UI 还会过滤短于 0.45 秒或少于两个字的结果。方向与 ASR 解耦后，这些限制不应影响指针。

下一步建议先用板端录音比较 5、10、15 秒片段的识别准确率、推理耗时和队列积压，再确定上限。若需要可靠的长语音转写，增加切段边界约 0.3–0.5 秒的音频重叠和文本去重，按时间顺序显示各段，明确提示跳段；不能只把上限改为 30 秒，因为那会增加结果等待和推理负载。

## 验收场景

- 正常说话开始后，ASR 尚未返回时指针已经显示；停顿和换说话者时方向能及时更新。
- ASR 模型加载慢、推理失败、队列满或被禁用时，实时指针持续工作。
- 方向未知的识别结果以纯文字出现在转写区，且不会把有效的实时指针清除。
- 使用固定六个方位、噪声、短句、连续说话 30 秒、USB 重插进行板端验证；记录首指向延迟、抖动次数、误指次数、ASR 丢段次数。
